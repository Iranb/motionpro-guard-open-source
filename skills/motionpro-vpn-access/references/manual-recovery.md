# 人工备用恢复与原状态交接

本路径需要解锁桌面和当前可用、已授权的电脑操作工具。没有工具、缺少保存凭据或须本人确认时，说明具体阻塞；不声称已操作。不要通过 shell UI 脚本、导出密码或猜测表单绕过工具规则。

## 接管

1. preflight 复核 0/7 持续约 30 秒。2/6 时验证目标并结束；连接中等待；未知状态先核实。
2. 观察 Guard 的阶段、进度与 deadline。活动恢复/配置事务未结束时等待，不抢锁、强杀或重启。
3. 在已有恢复授权范围运行 `python3 "SKILL_ROOT/scripts/handover.py" pause`。它核对实际签名 app 与现有任务，在共用恢复锁下记录原开关和加载状态，先卸载自身 watchdog，再卸载自身主任务；等待 Guard 释放生命周期锁后关闭策略。只操作 profile 指定且参数匹配的两项 Guard 任务，不停止官方 VPN。
4. `agent-handover.json` 保存在既有支持目录；不删除它或新建别的命名空间。任何步骤拒绝时保留 receipt，依据返回状态恢复或报告。默认 `inspect` 只读。KeepAlive 使单纯退出 app 不足以接管。
5. 运行 `manual_attempt.py status`。必须共用现有策略：每小时总计最多 2 次，连续两次失败暂停。策略不存在/损坏、其他 Guard 同时运行或接管不完整都拒绝，不把未知历史当作空预算。

## 实时表单与新口令

用当前电脑工具实际读取应用清单、AX 或截图；选择官方 MotionPro，确认网关/账号与当前授权一致。UI 变化后重读控件，不复用历史索引或随机 Translocation 路径。

保留客户端已保存静态密码，掩码不是可复制密码。缺少密码时由本人在系统/客户端正常输入。不要输出 `security ... -w` 或解密结果。

把已绑定的官方 OTP 页带到前台，确认计时器实际推进后取本轮口令，至少剩余 25 秒。分组数字与倒计时须按真实口令区域/位置区分；多实例、布局变化或来源不明时停止解析。不要把所有数字拼接。把 OTP 留在本机工具变量中，不写聊天、脚本、剪贴板、截图报告或任务文本。

更新实际的第二密码 / Password2 / 动态口令输入框。客户端“连接”可能直接使用已保存旧口令，在更新前不要盲点。

## 单次提交、结算与交还

```bash
python3 "SKILL_ROOT/scripts/manual_attempt.py" begin
```

记录返回的 attempt_id；脚本先持久化共享预算，才可以回到实时表单提交一次。返回拒绝就停止。取码/填表耗时导致过期时重新取新口令，预算不退回、不重复占位或点击。

约每 10 秒只读预检，等待隧道通常最多 120 秒，不叠加登录。2/6 为隧道成功；明确认证失败、超时或不明状态分开报告。

```bash
python3 "SKILL_ROOT/scripts/manual_attempt.py" finish --attempt-id ACTUAL_ID --outcome success
python3 "SKILL_ROOT/scripts/handover.py" resume
```

仅实际确认隧道登录成功使用 success；明确失败用 failure；结果不明用 unknown，后两者保守计入失败。结算相同结果可重复，人工成功不增加 Guard 自动归属计数。

resume 必须没有 pending 手动记录。它只恢复 receipt 中原开关和原来加载的任务，保留全部提交历史、失败暂停和新计数，不生成新任务、不重置预算。失败时也先按真实结果结算，再恢复原状态；不要把失败暂停解除。

最后验证原目标并继续任务；远程操作可能已执行时先查既有记录。此交接脚本经过合成环境测试，完整人工 UI 路径仍须按使用者当时的客户端实机核实；不为验证 skill 断开健康连接。
