# 备用界面恢复与预算交接

此路径需要可用且已授权的电脑操作工具和解锁桌面。调用方法以当前工具文档为准，不沿用旧截图、控件编号或历史账号。缺少条件时报告阻塞，不能把流程文档说成实际登录成功。

## 接管

1. 用 `scripts/preflight.py` 确认持续离线，记录 Guard 原启用开关和登录任务是否加载。连接中或已连接时等待/结束。
2. 等待 Guard 活动恢复结束。运行 `python3 install.py --disable-jobs` 明确卸载**公开版自己的**看护和主登录任务。它取得恢复锁，活动事务时拒绝停止；不会操作 VPN 客户端。不得使用单纯退出 app 来代替，因为 KeepAlive 会重新启动它。
3. 运行 `python3 scripts/manual_attempt.py pause`。取得生命周期锁后保存禁用策略，保留历史；记录返回的原开关状态。运行 `status` 检查预算。

## 表单与新口令

用实时界面确认默认网关和账号与当前授权一致。复用官方 MotionPro 保存的静态密码，掩码不是真实密码。缺失时让用户在本机正常凭据流程中处理，不导出明文或猜测密码。

在官方 OTP 前台确认自己的绑定，看到计时器推进后取本轮动态口令；剩余有效期至少 25 秒，临近过期则等新一轮。将值留在电脑操作工具的变量中，界面原文不输出到聊天。

更新实际表单的第二密码。连接按钮可能直接提交保存的旧第二密码，不能在更新前盲点。

## 预留、提交和结算

真正提交前运行：

```bash
python3 scripts/manual_attempt.py begin
```

记录返回的 `attempt_id` 后提交一次。脚本要求 Guard 已停、策略已关闭、无未结算记录、预算允许；失败时不绕过它。占位后即使操作中断也保留预算。

约每 10 秒做只读预检，通常最多等待 120 秒，不重复点击。Guard 仍停止时结算：

```bash
python3 scripts/manual_attempt.py finish --attempt-id ATTEMPT_ID --outcome success
```

明确失败用 `failure`；超时或结果不明用 `unknown`，两者保守计入失败。人工成功不增加 Guard 自动归属计数。

确认没有 pending 记录后，如果原来加载了登录任务，再运行 `python3 install.py --enable-jobs`。通过管理界面只恢复原来开启的自动恢复开关。不要解除失败暂停或清空计数。

这是一条待使用者实机验收的备用路径。任何步骤遇到工具、解锁、权限、预算或配置阻塞，都保持现场并报告。
