# 兼容性与已知限制

## 厂商配置适配

`VendorCipher` 的运行时适配固定了经过核对的官方客户端 SHA-256 和配置加密数据位置。固定哈希是厂商二进制兼容性标识，不是个人证书或令牌。

客户端版本不匹配时直接报 `unsupportedClient`，不会试探登录或自动猜测新格式。只从使用者已安装并获准使用的客户端取得运行时兼容材料；仓库和源码包不包含官方二进制、库或其加密密钥。

支持某一个构建不代表支持所有操作系统、Intel/Apple Silicon 厂商包或学校服务器。编译目标可以是 arm64/x86_64；实际厂商适配必须单独核对。GPL 许可适用于本仓库代码，不授予第三方客户端的重新分发权。

## 已知认证时间缺陷

当前 `LogHints.lastAuthentication()` 只读每个厂商日志末尾 320 KB。长会话的最新认证行被后续日志挤出范围后，`status.json` 的 `authenticatedAt` 可能回退到旧认证。

另一个归属限制是：厂商日志只精确到秒，Guard 提交记录精确到小数秒；如果认证与提交落在同一秒，严格的时间比较可能保守地归为未确认。连接正常时不会因此再次登录，但确认计数可能不增长。

这个字段不能单独用来推测自然到期时间。验收应提取完整日志中固定事件的时间戳，并避免公开原始日志。新登录通常在最新日志范围内，但也不能仅凭快照认定归属。公开整理保持原流程并明确此缺陷，尚未修改运行中本机版本。

## WidgetKit

小组件编译与签名属于构建检查。可见性、平台注册和读取快照的行为还依赖 macOS 的 WidgetKit/沙箱环境，需要在安装机器上检查。小组件未显示不等于隧道断开，也不证明主守护失效。主进程和命令行预检是恢复与验收依据。

## 时间与锁屏

Guard 检查时间连续性和边界余量，不向服务器校时，不试探服务器容忍窗口。系统绝对时间错误、令牌重绑或钥匙串拒绝都会影响恢复。开机未登录、关机和完全休眠也没有执行中的 Aqua 守护。

## 备用人工交接

`manual_attempt.py` 要求主程序停止并取得 `guard.lock`；运行中直接 `begin`/`finish` 会被拒绝。单纯退出 app 不能解决 KeepAlive 的重新拉起。文档使用明确的 `install.py --disable-jobs` 卸载公开版自己的看护/主任务，再协调人工预算。

暂停和脚本锁不允许绕过登录预算。备用流程需要电脑操作工具、解锁的桌面和当前表单核对。公开版交接尚未实机完成整轮 UI 登录验收；不能因为提供模板就宣称备用登录已验证。

## 验证范围

合成测试使用公开 RFC 向量和明确的虚构数据；不访问真实凭据或提交登录。测试及编译通过证明对应代码路径和构建可用，不证明任意生产环境可连接。

来源本机版本的一次自然锁屏恢复已观察成功。公开版重新标识与签名后的全流程、多日可靠性、备用 UI 登录，以及恢复后 SSH/HPC 业务连接仍需在使用者自己的环境验收。
