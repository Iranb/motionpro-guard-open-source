# 自然到期验收

保留已连接的 VPN，不为了验收主动断开。先从官方日志提取最近真实认证成功、L3 完成及历史服务端到期时间；只保留固定事件名和时间戳，不发布原始日志。

历史周期只能用于估计观察窗口，不能假设所有服务器都固定 24 小时。如有新的认证，重新估计。`connectedSince` 可能只是观察器开始时间；`authenticatedAt` 还有日志尾部截断的已知缺陷。

## 需要的证据

仅在明确的验收窗口内采样已有状态和锁屏状态；正常计划空闲期间不额外轮询 VPN，也不另建恢复任务。

1. `status.json` 中 generation、episode、attempt、提交时间、阶段与进度。
2. 事件顺序：计划到期 → 持续断线确认 → 安全 OTP 窗口 → 提交意图 → 启动确认 → 新认证及隧道连接；归属确认需核对对应事件与计数。
3. 厂商日志中提交后的新认证，以及完整 L3 成功回调，实时厂商状态为 2/6。
4. `confirmedSuccessCount` 从基线增长；锁屏成功应新增 `lockedSuccessDates`。
5. 恢复过程中独立的锁屏采样，Guard 对应事件 `locked=true`，以及无解锁/人工接管的证据。
6. 人工接管期、人工预算记录、备用任务和看护情况，用来排除混合恢复。

Guard 事件不保存 PID；独立审核可以核对事件链和计数，但 PID 因果判断仍依赖程序检查结果。约 10 秒锁屏采样也有采样粒度限制。

## 结果分类

| 结果 | 条件 |
| --- | --- |
| 已验证一轮自动恢复 | 同一尝试的新认证、L3、归属及确认计数齐全 |
| 已验证一轮锁屏恢复 | 上述条件加锁屏、锁屏成功记录和无接管证据 |
| 混合或归属不明 | 人工/备用介入，或连接成立但归属未确认 |
| 失败/阻塞 | 明确失败暂停、认证拒绝或条件长期不可用 |
| 尚无样本 | 预计窗口内没有自然到期事件 |

记录服务端到期到新 L3、提交到新 L3 的耗时，并说明采样粒度。先确认是否已经提交，避免重复登录。

一个成功周期只证明观察到的一次结果。程序累计三个不同本地日期的锁屏成功后会显示更高的观察等级，仍不代表所有未来环境可靠。VPN 恢复与目标 SSH、网页或 HPC 业务恢复分别验证。
