# 事件恢复、OTP 与持久化

## 计划与实时状态

默认 `official_profile` 后端通过原生文件通知监听 MotionPro 日志新增的断线、登出、会话失效与认证成功事件，并通过 `SCDynamicStore` 监听系统网络接口变化。历史日志不作为新事件重放；支持日志轮换、截断和分段行。通知只请求读取实时厂商状态，不直接发起登录。空闲期间没有固定间隔的 VPN 查询。

启动、唤醒、用户会话恢复，以及结束客户端前台操作也可触发检查。事件在一秒内合并；检查期间收到的事件保留到本轮结束，登录自身产生的事件不叠加认证。每次事件打开最长约 180 秒的观察窗口，约每 10 秒复查状态。

`LoginExpirySchedule` 另按可信的 `lastSuccessfulLoginAt` 加 24 小时和 120 秒安排一次性补充检查。缺少可信成功时间时不虚构起点；即使没有计划起点，原生事件仍可触发检查。

事件和到期检查按以下状态处理：

| 状态 | 处理 |
| --- | --- |
| 2/6，有隧道 | 保留连接；新认证重置起点，否则安排下一天 |
| 1/3/4，正在切换 | 在最长约 180 秒观察窗口内等待，不并行认证 |
| 0/7，离线 | 约 10 秒采样，连续约 30 秒确认后评估登录 |
| 暂时读不到状态 | 在同一有界窗口内复查；不授权登录 |
| 5，仅桌面连接 | 停止本轮，不按离线重启 |

提交认证后的隧道等待另有 180 秒上限。只有明确 0/7 状态连续约 30 秒、相邻采样间隔不超过 20 秒，才允许后续登录。未知状态不会计入断线时间。`connectionEventsReady=true` 表示至少一种原生监听已启动，不证明两种监听均可用。`automaticCheckMode=login_expiry` 表示到期补充计划，不能用旧快照证明实时隧道在线。

## 登录前检查

检查恢复开关、人工接管期、连续失败暂停、滚动小时预算、本地网络、网关可达、客户端兼容性、默认站点与官方数据源。取得共用 `recovery-control.lock`；生命周期 `guard.lock` 防止主进程重复运行。

从官方默认配置读取已保存的加密静态密码，只在内存中核对可解密，不重写该密码。每次重新读取当前官方 OTP 绑定，验证网关、格式和时间范围；不复用 Guard 的旧种子副本。

正常关闭已断线且不在解锁桌面前台操作的客户端。弹窗阻止退出时等待，不强杀。仅在厂商状态 0/7 且客户端完全退出时取得 `official-connector/operation.lock`，恢复旧配置事务并准备本轮登录。

## OTP 和时钟

当前适配使用 HMAC-SHA1 TOTP：10 字节种子、UTC 计数器、大端编码、动态截取和六位输出。周期必须是 30 秒的倍数，范围为 30–300 秒；这是本适配的已核对格式，不是所有 MotionPro 部署的保证。

厂商时间调整字段的正负契约尚未确认。实现只在 UTC 与两个可能偏移均处于同一周期时计算，并保留有效期余量。比较墙钟与单调时间，跳变或唤醒后等待稳定；不与服务器校时，也不尝试相邻口令。

等待期间和提交前重新核对官方源、账号、配置字节及至少 20 秒剩余有效期。当前源可读不代表本轮进行了官方窗口实时比较。

## 事务、提交与成功

`official-connector/pending.json` 与权限为 0600 的原配置备份保存自动连接、第二密码和相关重连字段。只注入本轮加密 OTP，静态密码保持原值。

真正启动前持久化共享预算和 `pendingOfficialAttempt`，然后通过原生启动 API 启动官方客户端一次。前置读取、等待和退出失败不计提交；提交结果未知时不重复认证。默认每滚动一小时最多两次提交，连续两次已提交失败暂停。显式授权的单次测试可使用有截止时间的 `oneTimeHourlyLimitOverrideUntil`：Guard 的下一次提交会消耗该字段，原提交记录保留，仍遵守失败暂停和人工接管限制。首次安装不设置测试额度，也不提供自动续期。

看到厂商状态 2/6 表示连接成立。新认证时间、Guard 启动的客户端归属和无人接管证据均匹配，才增加归属确认计数。成功后更新登录起点；已结束的预留记录从持久策略中清除，重启不会将其重新当作未完成。

连接后不恢复仍被客户端缓存的配置。确认正常断开且 GUI 退出后，下一轮恢复还原相关字段。只恢复仍等于本轮注入值或等价加密口令的字段。允许保留后来关闭的自动连接和恢复的会话失效处理设置，不让这些控制值阻止清理旧 OTP。其他不支持的控制值或已更改的口令仍保留事务和备份，不删除绕过。

## 数据与旧后端

公开版专用目录为 `~/Library/Application Support/MotionProGuardOSS/`：

| 文件 | 用途 |
| --- | --- |
| `status.json` | 最近状态、阶段、就绪条件及下次时间 |
| `recovery-policy.json` | 登录起点、已评估时间、预算、暂停及计数 |
| `official-connector/config.json` | 仅本机使用的源文件位置和端口 |
| `official-connector/pending.json` | 当前配置恢复事务 |
| `events/YYYY-MM-DD.jsonl` | 字段白名单的事件顺序 |
| `manual-attempt.json` | 人工备用预算和结算记录 |

Swift `Date` 数值以 2001-01-01 为起点，转换 Unix 秒需加 `978307200`。事件不记录账号、密码、种子、OTP 或 Cookie，不应上传真实事件文件。

源码保留旧钥匙串/窗口后端及实验原生会话适配。它们不作为默认入口；修改后端不能重置预算或绕过已知失败暂停。看护助手仅供显式诊断或受控恢复，没有自动周期，不管理 VPN 服务。
